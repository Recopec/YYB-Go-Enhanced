# YYB-Go 代理模块全链路架构与工作流规范

本文档全面梳理 YYB-Go 系统中代理模块的底层设计、生命周期管理、配置流转与防风控机制。

---

## 一、 核心设计思想

微信小程序及应用宝开放平台对登录与接口调用有两层核心限制：
1. **网络出口与地区特征**：部分政企/文旅/消费券小程序对用户登录 IP 所在省市有严格校验（如仅限云南、广东等）；
2. **频率控制与风控限制**：频繁使用同一公网出口批量发起 `wx.login` / `getCode` 容易触发微信的“操作过于频繁”或滑动验证码，甚至导致 Token 快速失效；
3. **长短效分离**：
   - **后台凭据保活（KeepAlive）**：需要网络长期稳定（每 1~2 小时刷新一次），**必须走直连或静态固定代理**；
   - **小程序取码发包（业务请求）**：往往需要特定地域 IP，通常使用**动态短效代理**。

为此，系统构建了**“全局配置库 + 账号维度独立绑定 + 长短效分离分流 + 租约复用缓存”**的四层代理体系。

---

## 二、 代理模式分类与机制

系统支持 4 种连接模式：

| 模式标识 (`mode`) | 类型 | 是否支持保活 | 适用场景 | 核心机制 |
| :--- | :--- | :---: | :--- | :--- |
| **`direct`（直连）** | 无代理 | ✅ 是 | 服务器网络干净、地区不敏感 | 绕过一切代理，直接走服务器网卡默认出口 |
| **`static`（静态代理）** | 固定出口 | ✅ 是 | 长期专享代理、自建家宽 SOCKS5/HTTP 隧道 | 原样复用固定 IP:端口及账号密码，支持长连接保活 |
| **`profile`（配置库）** | 模板化管理 | 视配置而定 | **最推荐方式**，统一管理品赞/巨量/静态预设 | 保存基础模板，不同账号按需选择省市或直接绑定静态预设 |
| **`api`（自定义动态 API）**| 短效动态 IP | ❌ 否 | 第三方私有提取链接 | 每次提取新 IP，支持常见 JSON/TXT 响应格式 |

## 三、 配置库（`proxy_provider_profiles`）运作机制

配置库将供应商的基础凭据与单个账号解耦，存储在 SQLite 表 `proxy_provider_profiles` 中：

### 1. 静态代理预设 (`provider: "static"`)
- **功能**：集中保存固定长效代理（如 `user:pass@1.2.3.4:8080`），设置名称（如“固定家宽 1”）。
- **优势**：添加账号或切换代理时，直接从下拉框点选即可，**无需每次手动敲 IP 端口和密码**。
- **调度**：绑定该预设的账号直接继承固定出口，自动隐藏省市选择，全天候用于扫码与后台保活。

### 2. 品赞代理 (`provider: "ipzan"`)
- **模板清洗**：添加品赞提取链接时，系统自动剔除原链接中的 `&area=...` 参数，仅保留订单号（`no`）与密钥（`secret`）。
- **动态重写**：当账号选择了具体省市（如“云南省 昆明市”）时，系统查内置区划编码表（`530100`），在向品赞发包前实时动态注入 `&area=530100`。
- **账密鉴权**：推荐 `mode=auth`，品赞返回动态账号密码（如 `account: DQGP...`, `password: plg...`），系统自动封装 Base64 代理鉴权头，**彻底摆脱公网 IP 白名单绑定限制**。

### 3. 巨量代理 (`provider: "juliang"`)
- **签名组装**：系统保存业务编号（`trade_no`）与密钥（`key`），依据账号所选省市自动拼接参数发包提取。
- **端点自愈**：按业务编号自动路由到后付费接口，并优先沿用用户粘贴链接中的端点。
- **鉴权只有白名单**：巨量不提供账号密码模式，每次提取固定带 `auto_white=1` 自动加白本机出口 IP；界面上不再提供“账号密码”选项，提交 `authorization_mode=auth` 会在保存时被拒绝。

## 四、 动态代理生命周期与 45秒租约缓存（Lease）

为防止并发发包导致短时间内疯狂向供应商拉 IP 消耗点数，系统在 `internal/httpapi/account_proxy.go` 内实现了**账号级代理租约（Lease）**机制：

```text
[发起业务请求] ──> 检查内存租约 (a.proxyLeases[accountID])
                       │
       ┌───────────────┴───────────────┐
       ▼                               ▼
[租约有效且未超 45s]           [租约过期 / 无租约]
直接复用当前提取的代理 IP       加排队互斥锁 (proxyLeaseLock)
连接腾讯服务器发包             调供应商 API 提取新鲜代理 IP
                               写入租约 (TTL = 45 秒) 后返回
```

- **45 秒黄金复用期**：同一账号在 45 秒内的多次小程序取码或数据操作，复用同一个外部出口，既保证业务上下文连贯，又极大节省代理点数；
- **排队互斥锁**：即使高并发打入，同一账号仅触发 1 次提取，其余并发协程等待复用，杜绝“并发击穿”导致瞬间扣除多份代理点数。

## 五、 扫码上号安全链路与防扣费闭环

用户在 `/scan` 页面扫码上号时，系统提供完整的额度防护链条：

1. **偏好记忆（Remember Selection）**：
   - 用户在页面选择的模式、协议、预设 ID、省份及城市，自动通过 `localStorage` 写入浏览器；
   - 下次打开扫码页面时，系统优先还原该配置，免去每次重复配置的繁琐。
2. **60 秒倒计时显化**：
   - 首次拉码或点击“应用到授权”时，启动居中大字号 **60 秒倒计时**；
   - 到期前倒计时每秒等宽跳动，提示用户及时扫码。
3. **失效熔断防烧点**：
   - 一旦 60 秒倒计时归零，或微信返回过期，系统立即执行 `handleQRExpired()`，**彻底停止一切自动刷新与长轮询**；
   - 二维码覆上失效蒙版，停止向代理商拉取 IP，杜绝因离开电脑导致点数被后台静默扣光。
4. **刷新二次确认（“我已知晓”）**：
   - 处于失效状态或挂载代理时，点击“重新生成”将弹出安全拦截模态框；
   - 界面明确提醒用户将扣减 1 次代理额度，**必须手动输入 `我已知晓`** 方可点亮刷新按钮。

## 六、 业务请求出口分流机制 (`protocol_proxy_mode`)

在账号代理设置中，可配置 `protocolProxyMode`（小程序调用出口）：

```text
               ┌── 扫码授权 (QR Login) ──────────> [账号绑定的代理]
               ├── 后台保活心跳 (KeepAlive) ───────> [账号绑定的代理]
[微信协议请求] ┤
               └── 小程序取码 (getCode / operateWxData)
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
    [模式: direct]                 [模式: account (默认，跟随账号)]
    绕过代理，直接走服务器出口发包      走账号绑定的代理出口
```

- **适用场景**：
  - 账号登录和保活需要长期保持在某个省市（如云南静态代理）；
  - 小程序业务对出口 IP 不敏感，直接直连发包速度更快、延迟更低；
  - 小程序调用默认跟随账号连接模式；出口无法承载 LongLink 或需要与账号分开时选择「直连」，两者互不干扰。

## 七、 常见问题与排查指南

1. **静态代理连接超时或鉴权失败**：
   - 检查协议是否选错（HTTP CONNECT 与 SOCKS5 不通用）；
   - 检查账号密码格式是否含特殊字符（如 `@`、`:`），特殊字符建议经过 URL 编码。
2. **品赞提示“IP 未在白名单”**：
   - 请在配置库中将授权方式切换为**「账号密码（推荐）」**，系统会自动读取返回的临时鉴权，无需维护服务器公网出口 IP。
3. **提示“短效代理不可用于保活”**：
   - 动态 API（1~5分钟套餐）仅用于临时取码，系统后台定时任务会跳过该类账号的主动保活，防止其无节制消耗代理额度。如需自动保活，请配置静态代理或使用直连。
